# Update Rules

**Purpose**: Evolve author-rules.md based on lessons learned, patterns detected, or new decisions

---

## Trigger Conditions

Run this command when:
- Editor provides feedback requiring new constraints
- Beta readers identify recurring issues
- Patterns emerge during writing
- Style decisions crystallize
- Mistakes need prevention
- Creative boundaries need definition

---

## Process

### 1. **Analyze Trigger**

#### Identify Source
- [ ] Editor feedback
- [ ] Beta reader comments
- [ ] Self-identified pattern
- [ ] Agent-detected issue
- [ ] Style evolution
- [ ] Genre requirement

#### Assess Impact
- Frequency of issue
- Severity of problem
- Reader impact
- Fix difficulty
- Prevention value

---

### 2. **Read Current Rules**

```markdown
## Load and Review
1. Read author-rules.md completely
2. Check Evolution Log for patterns
3. Note related existing rules
4. Identify correct category
5. Check for conflicts
```

---

### 3. **Determine Rule Type**

#### Hard Constraint (Never Break)
- Causes serious story problems
- Breaks reader immersion
- Violates genre contract
- Creates plot holes
- Damages character integrity

#### Soft Constraint (Avoid)
- Weakens prose
- Reduces impact
- Common pitfall
- Overdone trope
- Style weakness

#### Mandate (Always Do)
- Essential for quality
- Reader expectation
- Professional standard
- Story requirement
- Voice consistency

---

### 4. **Draft Rule**

#### Rule Format
```markdown
**[VERB + SPECIFIC ELEMENT]** - [Brief explanation]
Example: NO head-hopping - Maintain strict POV within scenes
Example: AVOID weather openings - Start with character/conflict
Example: MAINTAIN character voice - Each character speaks distinctly
```

#### Components
- Action verb (NO/AVOID/LIMIT/MAINTAIN/USE)
- Specific element
- Clear explanation
- Optional example
- Exception note (if any)

---

### 5. **Test Rule**

#### Validation Checks
- [ ] Clear and specific?
- [ ] Measurable/detectable?
- [ ] Improves quality?
- [ ] Doesn't conflict with existing rules?
- [ ] Reasonable to follow?
- [ ] Has clear value?

#### Impact Assessment
- How many existing scenes affected?
- Future writing difficulty?
- Creative limitation level?
- Reader benefit?
- Author benefit?

---

### 6. **Update Document**

#### Add to Correct Section
- Find appropriate category
- Insert in logical order
- Maintain formatting
- Update counts

#### Update Evolution Log
```markdown
[Date] - [Action] "[Rule]" [Reason]
Example:
2024-03-15 - Added "NO filter words" after editor feedback on Chapter 7
2024-03-16 - Modified "LIMIT flashbacks" from 1 per chapter to 1 per 3 chapters
```

---

### 7. **Document Pattern**

#### Pattern Entry Format
```markdown
## Pattern Detected: [Name]
Frequency: [X times in Y chapters]
Impact: [Reader/Story/Pace/Character]
Rule Added: [The new rule]
Prevention: [How rule helps]
```

## Common Rule Additions

- Pacing issues → Scene/chapter rules

- Lost threads → Continuity rules
- Emotional gaps → Development rules

### After Professional Editing
- Prose issues → Style rules
- Structure problems → Scene/chapter rules
- Dialogue problems → Voice rules
- Description issues → Balance rules
- Weak openings → Hook rules

### After Self-Review
- Repeated patterns → Constraint rules
- Overused words → Vocabulary rules
- Structural habits → Variation rules
- Character shortcuts → Development rules
- Plot conveniences → Logic rules

## Evolution Principles

### Good Rules Are:
- **Specific** - Not vague
- **Actionable** - Can be followed
- **Valuable** - Improve the work
- **Flexible** - Allow creativity
- **Clear** - No ambiguity

### Poor Rules Are:
- Too broad ("Write better")
- Too restrictive ("Never use 'was'")
- Unmeasurable ("Make it flow")
- Contradictory (conflicts with others)
- Arbitrary (no clear benefit)

5. **Test with next chapter** - Ensure workable

## Success Metrics

Rule update succeeds when:
- ✓ Issue addressed clearly
- ✓ Rule is followable
- ✓ No conflicts created
- ✓ Evolution log updated
- ✓ Pattern documented
- ✓ Future writing improved

---

## Common Mistakes

### Avoid:
- Over-correcting (too many rules)
- Vague rules (unmeasurable)
- Reactive rules (one-time issues)
- Restrictive rules (kills creativity)
- Conflicting rules (contradictions)

### Instead:
- Add thoughtfully
- Be specific
- Look for patterns
- Preserve creativity
- Check compatibility

---

*Rules should liberate creativity by removing doubt, not restrict it with fear.*
